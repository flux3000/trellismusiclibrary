**New file in your data folder.** On first launch, Trellis writes a small file called `install.json` that records when this install began. It goes in the folder above the one holding your database (by default `~/Library/Application Support/`, next to `avatars`). The path is resolved through symlinks, so if your database is a symlink the file goes next to the real database, not the link. A second node started with its own `TRELLIS_DB_PATH` gets its own file. The file holds a random install ID, the start date, which signal set that date, a schema number and the app version. It stays on your machine and is never sent anywhere. It is written once and never changed after that.

**Upgrades are dated from your original install.** If you already run 0.2.3 or earlier, the start date comes from your library, not from the day you upgrade. Trellis takes the earlier of two dates: when the owner account was created and when the database file was created. A fresh install with neither uses the current time. This happens on every kind of launch, server mode included. If the file can't be read or written (a read-only volume, for example), Trellis logs the error and starts normally.
